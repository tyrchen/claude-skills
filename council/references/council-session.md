# 圆桌讨论协议（Council Session Protocol）

> 多Advisor结构化辩论的完整执行规范

## 一、适用场景

圆桌讨论适用于以下情况：
- 重大决策需要多角度验证
- 问题跨越多个领域，单一视角不足
- 用户想看到不同思维方式的碰撞
- 需要识别盲区和隐含假设

**不适用的场景**：
- 纯事实性问题（直接搜索更高效）
- 只有1个Advisor可用（至少需要2个）
- 用户只想快速获得一个答案（单Advisor更快）

## 二、Advisor选择策略

### 自动推荐算法

当用户没指定Advisor时，按以下步骤推荐：

1. **扫描已有Advisor**：读取 `personas/*/persona.md` 的元数据头和心智模型section
2. **问题领域匹配**：将用户问题分解为关键维度（如：风险评估、商业策略、技术可行性、人际关系）
3. **互补性优先**：选择心智模型互补而非重叠的Advisor组合
4. **冲突是特性**：如果知道两个Advisor在某个维度上会有分歧，**优先选入**——分歧产生洞察

### 推荐模板

```
根据你的问题「[问题]」，我推荐以下圆桌组合：

1. **[Advisor A]** —— 带来[核心镜片]，擅长[X]维度
2. **[Advisor B]** —— 带来[核心镜片]，擅长[Y]维度
3. **[Advisor C]** —— 带来[核心镜片]，和A在[Z]上会有有趣的分歧

确认这个组合？还是你想加入/替换某个人？
```

### 组合禁忌

- 不要选3个心智模型高度重叠的Advisor（「三个芒格」没意义）
- 不要为了凑数加入与问题无关的Advisor
- 如果已有Advisor不足2个，提示用户先蒸馏

## 三、独立发言阶段（Round 1）

### Agent Spawn模板

为每个Advisor启动一个独立Agent，prompt如下：

```
你现在是[人名]。读取以下persona，完全进入这个角色。

[完整persona.md内容]

---

用户的问题是：
「[用户问题]」

请以[人名]的身份，用你的心智模型和表达方式回答。必须按以下格式输出：

## [人名] 的观点

### 我怎么看这个问题
分析时必须明确标注你用了哪个心智模型（用【模型名】标记），
解释为什么这个模型适用于此问题。

### 我的建议
给出具体、可行动的建议。不说正确的废话。

### 我最担心的是
基于你的价值观和反模式，这个问题最大的风险在哪里？

### 我的确定程度
[高/中/低]
理由：[说明哪些信息充足、哪些信息缺失会影响你的判断]

---
注意：
- 用第一人称「我」
- 用你自己的表达DNA（句式、词汇、节奏）
- 如果问题涉及需要事实的部分，按你的Agentic Protocol先研究再回答
- 不知道的就说不知道，但要说明如果有了哪些信息你的判断可能改变
- 将回答直接作为文本返回（圆桌讨论不需要写文件）
```

### 关键规则

- **独立性**：各Advisor的Agent之间不共享信息
- **深度**：每个发言300-500字，要有实质内容，不是泛泛而谈
- **标注模型**：每个分析必须追溯到具体的心智模型，这是后续辩论的锚点
- **并行执行**：所有Agent同时spawn，不等待
- **只返回内容**：Agent不写文件，主Agent负责所有IO

## 四、交叉质疑阶段（Round 2）

### 触发条件

所有独立发言收齐后自动进入。如果独立发言中各Advisor观点高度一致（共识度>80%），可以跳过此阶段直接综合——但要在报告中说明跳过原因。

### Agent Spawn模板

```
你现在是[人名]。读取以下persona，完全进入这个角色。

[完整persona.md内容]

---

其他Advisor的发言如下：

[Advisor A的完整发言]
[Advisor B的完整发言]
[Advisor C的完整发言（如有）]

---

请以[人名]的身份回应其他Advisor的观点。按以下格式输出：

## [人名] 的回应

### 我同意的部分
具体指出哪位Advisor的哪个观点你认同，用你自己的心智模型解释为什么。

### 我反对的部分
具体指出分歧点，必须追溯到心智模型层面的差异。
说明这个分歧的根源是：
- 前提不同？（你们对事实的理解不一样）
- 推理不同？（同样的事实，不同的分析路径）
- 价值观不同？（优化的目标不一样）

### 他们遗漏了什么
基于你独特的视角，指出其他人集体忽略的维度。

---
注意：
- 不要为了表面和谐而软化分歧
- 但也不要为了制造戏剧性而夸大分歧
- 引用对方观点时用原文，不歪曲
- 承认对方的观点在什么条件下是对的
- 将回答直接作为文本返回（圆桌讨论不需要写文件）
```

### 辩论深度控制

- **第一轮质疑**：必须执行
- **第二轮质疑**：仅当第一轮出现了**新的实质性论点**（不是重复）时执行
- **判断标准**：如果Advisor只是换了说法重复之前的立场，停止辩论
- **目标**：识别分歧的根源，而非说服对方

## 五、综合输出（Synthesis）

### 主Agent综合规则

主Agent不代表任何Advisor，作为中立主持人综合全部信息。

**综合时必须做的**：
1. 识别所有共识点并标注支持的Advisor数量
2. 绘制分歧图谱：谁和谁在什么问题上不同意，根源是什么
3. 将分歧转化为决策框架：不同优先级对应不同选择
4. 识别集体盲区：所有Advisor都没提到但可能重要的维度
5. 给出可行动的建议，而非「需要进一步分析」

**综合时绝不做的**：
- 不投票表决（「3:1所以这个观点对」是错误的逻辑）
- 不强求共识（真正的分歧比虚假的共识有价值）
- 不编造Advisor没说过的观点
- 不抹平有价值的矛盾

### 综合报告模板

```markdown
# Council圆桌报告：[问题]

**参与Advisor**：[Advisor A]（核心镜片）、[Advisor B]（核心镜片）、[Advisor C]（核心镜片）
**讨论轮次**：[N]轮

---

## 共识区
- **[观点1]**：[Advisor A/B/C]都认为... 因为...

## 分歧图谱

| 议题 | 正方 | 反方 | 分歧根源 |
|------|------|------|---------|
| [具体议题1] | [Advisor A]: [立场+模型] | [Advisor B]: [立场+模型] | [价值观/前提/推理]差异 |

## 决策框架

### 如果你最在意 [X]
→ 倾向 [Advisor A] 的建议
- 具体做法：[...]
- 代价：[...]

### 如果你最在意 [Y]
→ 倾向 [Advisor B] 的建议

### 综合方案（如果分歧可调和）
[说明为什么这不是和稀泥]

## 集体盲区
- [盲区1]：可能因为所有Advisor的模型都倾向于[X]，系统性忽略了[Y]

## 行动建议
1. [第一步]
2. [第二步]
```

## 六、追问机制

| 用户操作 | 处理方式 |
|---------|---------|
| 追问某个Advisor | Spawn该Advisor的Agent，带入完整讨论历史 |
| 加入新Advisor | 新Advisor先读所有历史发言，产出独立发言+回应 |
| 深挖某个分歧 | 相关Advisor进行第二轮交锋 |
| 请求裁决 | 每个Advisor被迫排序所有方案，说明底线条件 |
| 换个问题 | 结束当前session，开始新session |

## 七、质量标准

| 标准 | 检查方式 |
|------|---------|
| 每个Advisor的发言都能追溯到其心智模型 | 检查【模型名】标记 |
| 分歧有实质内容而非表面对立 | 检查分歧根源分类是否到位 |
| 决策框架给出了可行动的选择 | 检查是否有具体做法 |
| 集体盲区被识别 | 检查是否有超出所有Advisor模型的视角 |
| 综合没有歪曲任何Advisor的立场 | 交叉检查引用是否准确 |

## 八、与蒸馏的互动

- **发现新模型**：如果某个Advisor在讨论中展现了之前没提炼的思维模式 → 建议更新该persona
- **发现模型冲突**：如果某个Advisor的两个模型自相矛盾 → 标记为需要重新验证
- **发现新蒸馏需求**：如果讨论中发现缺少某领域视角 → 建议蒸馏新Advisor
